# TrackLine

Local telemetry comparison for Assetto Corsa Competizione. TrackLine discovers `.ld` logs under `Documents/Assetto Corsa Competizione/MoTeC`, reads MoTeC LD channels locally, and stores the preferred reference, imported paths, and best sector times in Electron's local application data.

## Run

Install Node.js 20 or newer, then run:

```powershell
npm.cmd install
npm.cmd run dev
```

Build a Windows installer with `npm.cmd run dist`. Use **Import** to select `.ld` logs outside the default directory. Matching `.ldx` sidecars are detected and basic XML vehicle, venue, and driver tags are used when available.

## Live coaching HUD

While ACC is running, TrackLine reads its shared memory (pedals, lap position, car coordinates, car and track) and compares it with the **fastest library lap for the same car and track**. The **LIVE** button in the header shows connection status, the reference lap in use, and settings.

- **HUD**: a transparent, click-through, always-on-top overlay with throttle and brake bars (you vs reference tick) and an HSI-style line indicator: a look-ahead ribbon of the reference line plus a deviation needle showing how far to move left or right in metres.
- **Hotkeys**: `Ctrl+Alt+H` shows or hides the HUD; `Ctrl+Alt+E` toggles edit mode to drag it and resize it with the corner grip. The layout is saved.
- **Display mode**: the overlay needs ACC in **Borderless** or **Windowed** mode; it cannot draw over exclusive fullscreen. Switch HUD mode to *Normal window* to show it on a second monitor instead.
- **Reference markers**: disable *Show coaching reference markers* in the LIVE panel to hide the reference pedal ticks, ghost arcs, and look-ahead warning arcs while keeping your own input display.
- **Look-ahead warnings and voice**: about 0.25 s before a braking or throttle zone (adjustable in the LIVE panel) a flashing arc appears outside the matching half-circle, sized to the % to apply. Separately, a female voice (Piper "amy") gives short, event-based callouts, never raw percentages: "Brake hard!" / "Brake." shortly before a braking zone, "Back on throttle." before corner exit, "Brake now!" if you miss the braking point, and "Release the brake." if you hold the brake after the reference lets go. It stays silent when you are already doing the right thing. Callouts pass through a single-slot scheduler with a 1–2 s cooldown (LIVE panel) that drops stale and duplicate cues; urgent ones bypass the cooldown. Clips live in `src/voice`; regenerate them with `node scripts/render-voice.cjs` (needs the Piper binary and voice model in `Assets/voice`). Voice and volume are in the LIVE panel.
- **Line calibration**: reference positions come from the MoTeC log and live positions from ACC, so TrackLine fits the two coordinate frames during your first full lap on a track (the HUD shows progress) and remembers the result. Pedal bars work immediately. If left/right looks inverted, enable *Swap left/right guidance* in the LIVE panel.
- **Pre-flight track briefing**: choose Monza, Spa-Francorchamps, or Nürburgring GP from **PRE-FLIGHT** to view sourced track boundaries and a live, iterative particle-swarm search for a low-curvature path constrained by track widths. The map shows the current best line and a faint candidate path as the search progresses, with its iteration count and an approximate lap-time score. The search starts from the bundled minimum-curvature line, uses finer sectors for chicanes, and scales its displayed lateral offsets to match the visually widened track. For Monza, the optimizer can use up to 92% of the sourced track width. When the matching Nissan GT-R MoTeC log is available, its fastest lap calibrates the optimizer's lateral, braking, and acceleration limits from speed and yaw-rate data, and logged brake/throttle inputs color the line. The log does not contain GPS position, so its yaw-integrated position is not treated as an exact lateral trace; the displayed path remains an optimization on sourced track geometry. Without that log, longitudinal colors are modeled estimates rather than pedal telemetry. The approach is inspired by the sector-based PSO method in [Racing-Line-Optimization-with-PSO](https://github.com/ParsaD23/Racing-Line-Optimization-with-PSO) and by trajectory-planning objectives in [TUMRT/online_3D_racing_line_planning](https://github.com/TUMRT/online_3D_racing_line_planning); it is an independent lightweight implementation, not a port of either project. The prior simulation gauge and pedal bars have been removed. Drag to pan, scroll or use the buttons to zoom, and use the rotate controls to rotate the map. Track widths are visually expanded for legibility; this does not change source geometry. Turn numbers remain selectable outside the track. Geometry comes from [TUMFTM/racetrack-database](https://github.com/TUMFTM/racetrack-database), pinned at revision `e59595d1f3573b30d1ded6a08984935b957688e0`; its centerlines originate from OpenStreetMap (© OpenStreetMap contributors, [ODbL 1.0](https://www.openstreetmap.org/copyright)), track widths were extracted from satellite imagery, and it warns that accuracy varies by venue. The bundled app includes the [LGPL-3.0 license](./public/licenses/TUMFTM-LICENSE.txt) and [track-data attribution](./public/licenses/TUMFTM-TRACK-DATA.txt). The score is a relative search objective, not ACC vehicle physics or a lap-time prediction; confirm layout, grip, and conditions in game.
- **GT3 reference-data generation**: run `npm run generate:gt3-reference -- --input "<MoTeC .ld file or folder>" --track monza --top-laps 5` to write `src/data/gt3-reference/monza.json`. The generator ranks valid Nissan GT-R laps by time, resamples the selected laps onto a uniform lap-distance profile, averages speed/pedal/yaw-rate values, and extracts brake/throttle zones with start/end distance, entry, minimum/apex, and exit speed. A measured position channel is required to extract the driver's actual line; the supplied Monza log has no GPS/world position, so its generated shared line explicitly falls back to the bundled TUMFTM minimum-curvature line instead of misrepresenting yaw-integrated position as a GT-R trace. The per-track JSON separates the shared x/z line from the GT-R speed/pedal profile and includes per-car zone adjustments. Add a car with normalized mass/power/downforce/brake-performance ratios to `src/data/gt3-reference/car-parameters.json`, then regenerate. `electron/gt3-reference.cjs` exports `adjustZonesForCar(dataset, parameters)` to calculate bounded first-order braking-point, corner-speed, and acceleration-zone adjustments for any added GT3 car; set ratios from ACC 1.10 BoP/setup data and validate against telemetry before relying on them. The generator accepts `--car-config <path>` to use another config file.
- **Lap replay HUDs**: lap analysis shows separate reference and driver gauges synchronized to replay and scrubbing, with recorded speed, throttle, and brake. MoTeC samples do not currently provide the live HUD's RPM, gear, fuel, or tyre readings, so those values are not invented.
- **Post-session setup quiz**: after at least one minute of driving or a completed lap, TrackLine asks whether understeer/oversteer happened on entry, mid-corner, or exit, as well as braking stability, tyre pressure/temperature, or overall balance. Handling answers adjust one relevant setting by one click and save a separate native ACC JSON; the original is never overwritten. For tyre advice, enter the four in-game hot pressures and tyre temperatures and choose dry/wet conditions. For GT3 setups, TrackLine uses the published dry/wet hot-pressure windows, adjusts imported native starting pressures by at most 1 psi per tyre, and skips pressure changes when any entered temperature is outside the 70–100°C working window. It saves other car classes without pressure changes because their native pressure scales may differ. This is a conservative starting point: temperature can signal issues beyond pressure, and conditions and car/version-specific targets still matter. The balanced answer saves an unchanged baseline copy. If there is no template setup for the car, import one when prompted.
- **Nissan GT-R 2018 reference**: for Monza quiz sessions, TrackLine shows values from a community setup file explicitly labelled for the Nissan GT-R 2018 and ACC v1.10 (front/rear anti-roll bar 4/2, brake-bias JSON value 36, differential preload 0). This track-specific reference is for comparison only; it is not an official or universal setup and is never copied over the user's imported setup. Handling suggestions remain single-click changes to the imported setup.
- **Tyre feedback**: the LIVE panel reads live pressures and core temperatures and can import an ACC setup JSON from `Documents/Assetto Corsa Competizione/Setups`. After several stable laps, it compares live dry pressure against a 26–27.2 psi hot range and suggests a small next-run starting-pressure change. ACC setup pressure values are car-specific encoded values, so TrackLine displays them as native values rather than guessing their PSI conversion. In the post-session quiz, automatic starting-pressure edits are currently limited to GT3 setups; for other classes such as GT4, TrackLine saves a copy without changing pressures because the native PSI scale differs. Confirm weather and the car's current target; core temperatures are not tread-surface readings and cannot guide camber.

## Telemetry notes

The bundled reader decodes numeric MoTeC LD channels, including embedded car, venue, date, distance, speed, timing, pedal, and GPS/world-position channels when present. Channel names vary between logger profiles. Logs without position channels still show their circuit outline and pedal traces. Logs without both distance and usable speed/time channels cannot produce accurate sector timing.

Sector boundaries are approximated at equal thirds of lap distance in v1. Personal bests are retained per detected or overridden car and track. The optimal time sums each best sector and is theoretical; telemetry is not stitched into a synthetic lap.

No accounts or remote services are used. Lap files stay in their original locations; user preferences are stored locally. The interface uses installed fonts and makes no external requests.

## ACC setup references

- [The Ultimate ACC Car Setup Guide](https://coachdaveacademy.com/tutorials/the-ultimate-acc-car-setup-guide/) — dry/wet hot-pressure targets and the effects of brake bias and anti-roll bars on balance.
- [How to Set the Correct Tyre Pressures in ACC](https://coachdaveacademy.com/tutorials/how-to-set-the-correct-tyre-pressures-in-acc/) — assess pressures after several laps and adjust starting pressures to reach the running target.
- [Race Element ACC setup model](https://github.com/RiddleTime/Race-Element/blob/63795df188ad4e7c7b319751d0765c423fca066e/Race_Element.Data.ACC/SetupParser/SetupJson.cs) and [pressure converter](https://github.com/RiddleTime/Race-Element/blob/63795df188ad4e7c7b319751d0765c423fca066e/Race_Element.Data.ACC/SetupParser/SetupConverter.cs#L203-L208) — community implementation references for the native JSON structure and car-specific pressure scaling (GT3 20.3–35.0 psi; GT4 17.0–35.0 psi). They are not official Kunos specifications.
- [Community Nissan GT-R 2018 v1.10 Monza setup](https://github.com/Lon3035/ACC_Setups/blob/11f41f9bba08e4ed39566e2be6ac893651e2f09b/nissan_gt_r_gt3_2018/monza/FRI3_GTR18_BASE_v1.10.json) — a version-labelled, track-specific reference setup; not an official baseline.
